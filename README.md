# X タイムライン自動収集ツール

X(旧Twitter)の **おすすめ欄** と **フォロー欄** から、公式APIを使わずに
投稿テキスト(コメント)と画像を自動で収集するツールです。
Playwright によるブラウザ自動操作で、タブごとに **約10アカウント分** の投稿を取得します。

> ⚠️ **注意**: 自動化ツールによる収集は X の利用規約に抵触する可能性があり、
> アカウントが制限・凍結されるリスクがあります。自己責任で、自分のアカウントに対して、
> 節度ある頻度でご利用ください。収集したデータの取り扱いは各自の責任で行ってください。

## かんたんな使い方(Windows・ダブルクリックでOK)

1. **[Node.js](https://nodejs.org/ja)** の LTS 版をインストール(初回の一度だけ)
2. このフォルダの **`start.bat` をダブルクリック**

初回だけ自動でセットアップ(必要な部品とブラウザのダウンロード)が走り、
以降はダブルクリックだけでメニュー画面が開きます。

```
==== メニュー ====
  1. 収集を開始(投稿・画像・コメント)
  2. ログインアカウント管理
  3. 保存先フォルダの設定
  4. フォロー中アカウントを出力
  5. おすすめ欄のアカウントを収集
  6. アカウントを移植(一覧を安全にフォロー)
  7. 5アカウント同時表示(マルチビュー)
  8. 終了
```

- **1. 収集を開始** — 質問に答える(全部 Enter でおすすめ設定)と収集が始まり、
  終わると HTMLレポートが自動でブラウザに開きます。
  初回はログイン画面が開くので、アカウント登録済みなら自動ログイン、
  未登録なら手動でログインしてください(セッションは保存され次回から不要)。
- **2. ログインアカウント管理** — 対象アカウントのユーザー名・パスワードを
  追加/編集/削除、使用アカウントの切り替えができます(下記参照)。
- **3. 保存先フォルダの設定** — 保存先をフォルダ選択ダイアログまたは手入力で指定できます。
- **4. フォロー中アカウントを出力** — 使用中アカウントの「フォロー中」一覧を取得します(下記参照)。
- **5. おすすめ欄のアカウントを収集** — おすすめ欄に出てくるアカウントを集めます(下記参照)。
- **6. アカウントを移植** — 4や5で作った一覧を、別アカウントで安全に一括フォローします(下記参照)。
- **7. 5アカウント同時表示** — 複数アカウントを別々のウィンドウで並べて表示します(下記参照)。
- **8. 終了** — アプリを終了します(シャットダウン)。

> ⚠️ **注意**: 自動化ツールによる収集は X の利用規約に抵触する可能性があり、
> アカウントが制限・凍結されるリスクがあります。自己責任で、自分のアカウントに対して、
> 節度ある頻度でご利用ください。収集したデータの取り扱いは各自の責任で行ってください。

## ログインアカウント管理

メニューの **2** から、対象アカウントを登録・編集できます。

- **追加(a)**: 表示名・ユーザー名(メール/電話でも可)・パスワードを入力
- **編集(e)/削除(d)**: 登録済みアカウントの内容変更・削除
- **使用アカウント切替(s)**: 複数登録した中から今回使うアカウントを選択(0で手動ログイン)

パスワードを登録すると、次回のログインは **人間らしい入力速度で自動ログイン** します
(2段階認証や画像認証が出た場合は、開いたブラウザで操作すれば続行します)。
パスワードを空にしておくと、毎回ブラウザで手動ログインする方式になります。

> 🔐 アカウント情報は **お使いのPC内の `config/settings.json` にのみ保存** され、
> GitHub などには一切送信されません(`.gitignore` 済み)。パスワードは平文で保存されるため、
> 共用PCでの利用は避けてください。

## 5アカウント同時表示(マルチビュー)

メニュー **7** で、複数アカウントを **別々のウィンドウで同時に表示** できます。
アカウントごとにログインセッションが分かれているので、
**5アカウントに同時にログインしたまま**、それぞれを自由に操作できます。

```
画面を自動でタイル状に分割(1920x1080の場合)
┌─────────┬─────────┬─────────┐
│ アカウント1 │ アカウント2 │ アカウント3 │   上段3つ (640x540)
├─────────┴────┬────┴─────────┤
│  アカウント4     │  アカウント5     │   下段2つ (960x540)
└──────────────┴──────────────┘
```

### 使い方

1. メニュー **2** で表示したいアカウントを登録しておく
2. メニュー **7** を選ぶ
3. 表示するアカウントの番号を入力(空Enter で先頭から5件)
4. ウィンドウが並んで開きます。**各ウィンドウは普通のブラウザとして自由に操作できます**

### 表示中にできる一括操作

開いている間、コンソールから全ウィンドウをまとめて操作できます:

| 操作 | 内容 |
|---|---|
| 1 | 全ウィンドウをホームに移動 |
| 2 | 全ウィンドウを指定のユーザー/URLへ移動(`@handle` でも URL でも可) |
| 3 | 全ウィンドウを再読み込み |
| 4 | 各ウィンドウが今どのページを開いているか表示 |
| 5 | 全ウィンドウを閉じてメニューに戻る |

「全アカウントで同じ投稿を開く」「全アカウントのタイムラインを一度に更新する」
といった使い方ができます。

- ウィンドウ枚数と列数は `src/config.js` の `maxParallelViews` / `viewColumns` で変更できます
- 画面サイズは自動検出し、それに合わせてタイル配置します
- 閉じるときに各アカウントのログイン状態が保存されるので、次回はそのまま開けます
- ログインが切れているアカウントがあれば、開いた直後に名前を挙げて知らせます

> 💡 5つのブラウザを同時に動かすためメモリを多く使います。動作が重い場合は
> `maxParallelViews` を 3 程度に減らしてください。

## フォローの出力とアカウント移植

「今のアカウントのフォロー先を、新しいアカウントにそのまま引き継ぎたい」
「おすすめに出てくる良さそうなアカウントを、別アカウントでまとめてフォローしたい」
といった用途に対応します。すべて **API不使用・人間らしい操作** で行います。

### 手順(例:アカウントAのフォローをアカウントBに移植)

1. メニュー **2** でアカウントA・Bを登録し、**A** を使用アカウントにする
2. メニュー **4「フォロー中アカウントを出力」** を実行
   → `保存先/lists/following_<A>_<日時>.txt`(と .json / .csv)に一覧が保存されます
3. メニュー **2** で使用アカウントを **B** に切り替える
4. メニュー **6「アカウントを移植」** を実行し、2で作った一覧を選ぶ
   → 確認のうえ、Bのアカウントで安全にフォローが実行されます

**おすすめ欄からの移植** も同様です。メニュー **5「おすすめ欄のアカウントを収集」** で
`recommend_accounts_<日時>.txt` を作り、アカウントを切り替えてから **6** で一括フォローします。

### 安全のための制限(BAN対策)

短時間の大量フォローはアカウント制限・凍結の原因になります。そのため:

- **1回の実行でフォローする件数に上限**(既定 **20件**)
- **1件ごとに 25〜60秒のランダム待機**(人間が手で押すくらいの間隔)
- **すでにフォロー済みのアカウントは自動でスキップ**、自分自身も除外
- プロフィールを開く前後の待機・マウス移動など、機械的でない動き

一覧が上限を超える場合は、**時間をおいて 6 を再実行**すると続きをフォローします
(既にフォローした分は自動でスキップされます)。上限や間隔は `src/config.js` の
`maxFollowsPerRun` / `followDelayMinMs` / `followDelayMaxMs` で調整できます。

> ⚠️ 上限を上げるほどリスクも上がります。特に新規アカウントは制限されやすいため、
> 1日あたりの合計フォロー数は控えめ(数十件程度まで)にすることを強く推奨します。

## 保存されるデータ

各投稿について、以下をすべて保存します:

| 項目 | 保存先 |
|---|---|
| **アカウント名**(表示名・@ID) | `tweets.json` / `report.html` / `tweets.csv` |
| **コメント**(投稿本文) | 同上 |
| **投稿時間**(日時) | 同上(ISO形式) |
| **画像**(最高画質) | `images/` フォルダに実ファイル、URLもJSONに記録 |
| **リプライ**(コメント欄) | `tweets.json` / `report.html`(投稿者名・本文・画像) |

## 失敗の検知と自動補正

途中で失敗しても、**種類を見分けて自動で立て直す**ようにしています。
「気づいたら止まっていた」「途中で全部消えた」を防ぐ仕組みです。

| 起きたこと | 自動でどうするか |
|---|---|
| 通信エラー・タイムアウト | 2秒→4秒→8秒と間隔を空けて**最大3回やり直す** |
| Xのエラー画面(「問題が発生しました」) | **再試行ボタンを押す**か再読み込みして続行 |
| レート制限 | **1分→2分→4分**と待ち時間を伸ばして自動再開(最大10分) |
| ログインセッション切れ | **自動で再ログインして、続きから再開** |
| タブ名が変わった(X側の仕様変更) | 名前で見つからなければ**位置(1番目/2番目)で切り替え** |
| 投稿が読み込まれず止まった | ページ状態を確認して**再読み込み**、それでもダメなら取得済み分を保存して終了 |
| 画像が取得できない | 待って**3回まで再取得**、それでもダメなら**画質を下げて**取得 |
| 投稿1件の取得に失敗 | その1件だけ飛ばして**残りは続行**(全体を止めない) |
| フォローが反映されない | **押し直して確認**。制限が原因なら安全に中断 |
| フォロー数の制限に達した | **その場で中断**し、残りを `remaining_*.txt` に保存(あとで続きから実行可能) |
| パスワード誤り・2段階認証 | 原因を判別して表示し、**手動操作に切り替え**て続行 |

失敗したものは `errors.json` に記録され、実行後に件数が表示されます。
**一部が失敗しても、成功した分のレポートと画像は必ず保存されます。**

## 検知(BAN)対策 — 人間らしい挙動

自動化と気づかれにくくするため、機械的な動きを避けています:

- スクロールは一気にではなく **小刻みに**、たまに少し戻って読み返す
- 各操作の合間に **ランダムな待機**(ときどき長めに「考え込む」)
- **マウスを画面内で自然に移動**
- 自動ログイン時は **1文字ずつ、ばらついた速度でタイプ**(たまに手が止まる)

> それでも過度な頻度・件数はリスクになります。控えめな回数でのご利用を推奨します。

## 機能まとめ

- **API不使用**: Playwright のブラウザ自動操作で収集(日本語/英語UI対応、広告除外)
- **約10アカウント分** の投稿テキスト・画像(最高画質)・リプライを収集
- **ダブルクリック起動**(`start.bat`)とメニューからの終了(シャットダウン)
- **ログインアカウント管理**: 複数アカウントの登録・自動ログイン
- **保存先フォルダの選択**: ダイアログまたは手入力
- **HTMLレポート自動生成** + **CSV出力**(Excel対応)
- **差分取得**: 取得済みの投稿は次回スキップ
- **キーワード絞り込み**
- **失敗の検知と自動補正**: 通信エラー・セッション切れ・レート制限などを自動で立て直し
- **フォロー中一覧の出力**(JSON/TXT/CSV)
- **おすすめ欄アカウントの収集**
- **アカウント移植**: 一覧を別アカウントで安全に一括フォロー(上限・間隔つき)
- **5アカウント同時表示**: 複数アカウントをタイル状に並べて同時操作
- **人間らしい挙動**でBANリスクを低減

### コマンドで直接実行したい場合(上級者向け)

```bash
npm start                   # メニュー画面(start.bat と同じ)
npm run scrape              # おすすめ + フォロー中 の両方(質問なし)
npm run scrape:recommend    # おすすめ欄のみ
npm run scrape:following    # フォロー欄のみ
npm run login               # 使用中アカウントでログインし直す
```

## 設定

ふだんは `npm start` の質問で足りますが、細かい調整は `src/config.js` で変更できます:

| 設定 | 既定値 | 説明 |
|---|---|---|
| `maxAccounts` | `10` | タブごとに収集するアカウント数 |
| `maxTweetsPerAccount` | `5` | 1アカウントあたり保存する投稿数 |
| `fetchReplies` | `true` | 各投稿のリプライ(コメント)も取得するか |
| `maxRepliesPerTweet` | `10` | 1投稿あたりのリプライ取得数 |
| `skipSeen` | `true` | 取得済み投稿をスキップ(差分取得) |
| `keywords` | `[]` | キーワード絞り込み(空=すべて) |
| `maxScrolls` | `30` | タイムラインの最大スクロール回数 |
| `maxScrolls` | `30` | タイムラインの最大スクロール回数 |
| `maxParallelViews` | `5` | 同時表示するウィンドウの最大数 |
| `viewColumns` | `null` | タイル配置の列数(`null` で枚数に応じて自動) |
| `maxFollowsPerRun` | `20` | 1回の実行でフォローする上限 |
| `headless` | `true` | `false` にするとブラウザの動作を目視できます |

保存先とログインアカウントはメニュー(`start.bat`)から設定でき、`config/settings.json` に保存されます。

## 仕組み

- `src/index.js` — メニュー画面(`start.bat` / `npm start`)。収集・アカウント管理・保存先設定
- `src/login.js` — 自動/手動ログインでセッション(Cookie)を保存
- `src/scrape.js` — ホーム画面でタブを切り替え、人間らしくスクロールして投稿を収集
- `src/extract.js` — DOM から投稿ID・本文・投稿日時・画像URLを抽出(広告は除外)
- `src/report.js` — HTMLレポートとCSVの生成
- `src/multiview.js` — 複数アカウントの同時表示(ウィンドウのタイル配置・一括操作)
- `src/resilience.js` — 失敗の検知(セッション切れ・レート制限・エラー画面)と自動補正
- `src/follows.js` — フォロー中の出力・おすすめアカウント収集・安全な一括フォロー
- `src/lists.js` — アカウント一覧の保存(JSON/TXT/CSV)と読み込み
- `src/settings.js` — ログインアカウント・保存先などの設定管理
- `src/humanize.js` — 人間らしい待機・スクロール・タイプ入力
- `src/pickFolder.js` — 保存先フォルダ選択ダイアログ(Windows/macOS/Linux対応)
- 画像は `name=orig`(オリジナル画質)に変換してダウンロード

## トラブルシューティング

- **Node.js が無いと言われる** → [nodejs.org](https://nodejs.org/ja) の LTS 版を入れて `start.bat` を再実行
- **一部だけ取得できなかった** → 保存先の `errors.json` に理由が記録されています。時間をおいて再実行すると取り直せます
- **「レート制限に達しました」** → Xからの一時的な制限です。30分〜1時間おいて再実行してください
- **フォローが途中で止まった** → 制限に達しています。`remaining_*.txt` に残りが保存されているので、時間をおいて「6」で続きを実行してください
- **「タブが見つかりませんでした」** → セッション切れの可能性。もう一度ログインしてください
- **自動ログインが止まる** → 2段階認証や画像認証の可能性。開いたブラウザで操作すると続行します
- **新しい投稿が取得できない** → 差分取得が効いています。保存先の `seen.json` を削除すると最初から取得します
- **動作を目で見たい** → `src/config.js` の `headless` を `false` にして実行
- **ブラウザが見つからない** → `npx playwright install chromium` を実行、または環境変数 `CHROMIUM_PATH` で実行ファイルを指定
